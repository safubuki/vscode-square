# Antigravity 終了残り・メモリ使用量 解析レポート

**日時**: 2026-08-24  
**深刻度**: 🟠 Major（終了残り） / 🟡 Minor（メモリ改善余地）

## 概要

Antigravity から VS Code へ切り替えた場合や、パネルの「閉じる」を使った場合に、旧ウィンドウが背後へ残り得るコード経路を確認した。原因は `WM_CLOSE` の送信成功をウィンドウ終了成功として扱い、HWND が実際に破棄される前にスロットの管理情報を消していたことだった。

メモリについては、既定および現在のユーザー設定が VS Code 標準プロファイル共有になっており、スロット別キャッシュの4重化は既に回避されている。安全性を損なう強制メモリ解放は追加せず、残存ウィンドウを確実に閉じることで不要になった IDE / renderer のメモリが自然に解放される状態へ修正した。

## 発生していた問題

| # | 問題 | 原因 | 対応 |
|---|---|---|---|
| B1 | 閉じる操作後も Antigravity ウィンドウが残り得る | `PostMessage(WM_CLOSE)` が true を返した直後に管理情報を消していた | HWND 消滅を最大8秒確認し、確認後だけ管理解除する |
| B2 | Antigravity → VS Code 切替で旧ウィンドウと新ウィンドウが併存し得る | 従来の最大1.2秒待機後も HWND が生存しているかを成功条件にしていなかった | 終了未確認時は旧 HWND を保持したまま切替を中止する |
| B3 | 4ウィンドウ利用時のメモリ圧迫 | IDE が Electron の renderer / extension host 等をウィンドウごとに持つ | 残存ウィンドウ解消のみ実施。危険または一時的な強制 trim は不採用 |

## 原因の詳細

- `WindowArranger.Close` は Win32 の `PostMessage(WM_CLOSE)` を呼ぶ。戻り値はメッセージをキューへ送れたことを示すだけで、対象ウィンドウの破棄完了を保証しない。
- 個別の「閉じる」と「一括閉じる」は送信直後に `StatusStore.ClearWindow` を呼んでいた。
- アプリ切替とパネル情報削除は短時間ポーリングしていたが、時間切れ後も生存 HWND を成功扱いして管理解除していた。
- Antigravity のような Electron 系 IDE が終了処理、未保存確認、拡張機能停止に時間を使うと、パネルだけが HWND を見失う状態が成立する。

## 実装した対策

- `ManagedWindowCloseService` を追加し、`WM_CLOSE` 送信後に HWND が消えるまで100ms間隔・最大8秒待つ。
- 「個別閉じる」「一括閉じる」「IDE/CLI切替」「控え移動」「パネル情報削除」の全経路を同じ終了確認へ統一する。
- 終了要求の拒否またはタイムアウト時は、スロットの HWND と保存情報を残し、切替・移動・削除を中止する。
- 一括閉じるは4ウィンドウへ並列に要求して待ち、最大待機を合計32秒へ伸ばさない。
- 終了未確認を `panel.log` に HWND、application ID、結果付きで記録する。

## メモリ調査と判断

- 現在のユーザー設定は `useDedicatedUserDataDirs=false` / `inheritMainUserState=false` で、既知の4重 user-data / cache 問題は発生しない構成だった。
- 調査時の一時点では、VS Code の可視ウィンドウ1つに対して `Code` 系13プロセス、合計 working set 約2.3GBだった。値は開いているタブ、拡張機能、AIセッション等で変動するが、メモリの大半が外部 Electron IDE 側であることを確認した。
- パネル側の周期処理は4スロットの HWND・タイトル・workspaceStorage を更新する軽量処理で、ウィンドウ数に比例して大容量データを保持する構造は見つからなかった。
- `EmptyWorkingSet` 等の強制 trim は表示上の working set を一時的に下げてもページフォルトと操作遅延を増やすため不採用。
- `--disable-gpu`、`--disable-extensions`、プロセス強制終了は描画問題、AI拡張停止、未保存データ消失を招くため既定動作へ追加しない。

## 回帰テスト

`TurtleAIQuartetHub.Panel.Tests` の依存パッケージ不要なテストで次を確認する。

1. 既に消滅した HWND は close を再送せず成功する。
2. `WM_CLOSE` 送信失敗を成功扱いしない。
3. 遅れて消滅する HWND は消滅確認後だけ成功する。
4. 待機期限ちょうどに消滅した HWND を取りこぼさない。
5. 残り続ける HWND はタイムアウトとなり成功扱いしない。

## 手動 QA

1. Antigravity を起動し、パネルの「閉じる」でウィンドウが消えた後にだけ未起動表示へ変わること。
2. Antigravity から VS Code へ切り替え、旧 Antigravity ウィンドウが消えてから VS Code が起動すること。
3. 未保存確認でキャンセルした場合、8秒後に切替が中止され、Antigravity が元スロットの管理対象として残ること。
4. 一括閉じるで終了できなかったウィンドウだけが管理対象に残り、成功件数・未終了件数が表示されること。
